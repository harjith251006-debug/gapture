# 1. PRODUCT OVERVIEW

## 1.1 Product Name

**FT-07 — Regulatory Compliance Intelligence Platform**

## 1.2 Product Purpose

FT-07 is a regulatory monitoring and AI-assisted compliance information system designed to continuously monitor the official websites of:

- **RBI — Reserve Bank of India**
- **SEBI — Securities and Exchange Board of India**

The system automatically web-scrapes these regulatory websites for new notifications/documents. A backend **Source Monitoring Platform** continuously performs this monitoring and passes detected information to the **Watchdog Extraction** component.

When a new file is detected, the system processes it through:

**Web Scraping → Watchdog Extraction → File Detection → OCR → SHA256 / Encryption → Store Original → Document Cleaning → NLP → Company Compliance Policy Comparison → 1-Line / Detailed / Summary → Supabase Backend → Web Application → Notification → View → Voice Button → 11Labs → Contextual LLM Question Handling**

If no file is found, the system returns to the continuous monitoring loop.

# 5. PRODUCT OBJECTIVES

## 5.1 Primary Objective

To continuously monitor RBI and SEBI websites through backend web scraping and identify new regulatory notifications/files.

## 5.2 Document Processing Objective

When a new file is detected, the system shall process the document through OCR, SHA256/encryption, original-document storage and document cleaning.

## 5.3 Intelligence Objective

The system shall use NLP to analyze the cleaned OCR data and compare it against trained company compliance policies.

## 5.4 Information Delivery Objective

The system shall produce:

- 1-line information
- Detailed information
- Summary information

and make the information available through the Supabase Backend and Web Application.

## 5.5 Notification Objective

The system shall notify users to log in when relevant new regulatory information becomes available.

The notification shall use:

- **1-line NLP output as title**
- **Summary NLP output as description**

## 5.6 AI Interaction Objective

After the user views the information, the user can use the Voice Button, which triggers 11Labs and enables an LLM to handle questions with respect to the relevant context.

## FR-02 — SOURCE MONITORING PLATFORM

### Purpose

The Source Monitoring Platform is a **backend file/service responsible for web scraping the RBI and SEBI websites for new notifications/files**.

This is the first active backend processing component after the regulatory sources.

### Flow

```text
RBI / SEBI
     ↓
SOURCE MONITORING PLATFORM
     ↓
WATCHDOG EXTRACTION
```

### Responsibilities

The Source Monitoring Platform shall:

1. Access the RBI website.
2. Access the SEBI website.
3. Web-scrape the relevant regulatory pages.
4. Continuously check for new notifications/files.
5. Extract information necessary for identifying newly available files.
6. Pass the extracted source information to Watchdog Extraction.
7. Participate in the continuous monitoring loop.

### Nature of Component

This is a **backend component**.

It is not the Web Application.

It operates independently in the background to monitor regulatory sources.

### Input

- RBI website
- SEBI website

### Output

- Scraped source information
- Potentially detected notification/file information

### RSS Feed Tracking

The Source Monitoring Platform may use **RSS feeds for feed tracking** where an RSS feed is available for the relevant regulatory source. RSS is used as a source-monitoring mechanism for tracking new notifications/files.

### Technology Boundary

The workflow does not mandate a particular web-scraping library or programming language.

Therefore, this PRD does not require a specific scraping framework.

The architecture team can determine the appropriate implementation technology.

## FR-05 — CONTINUOUS MONITORING LOOP

### Purpose

The system shall continuously monitor RBI and SEBI for new files.

When Watchdog Extraction determines that no new file has been found, the monitoring process shall continue.

### Flow

```text
SOURCE MONITORING PLATFORM
          ↓
WATCHDOG EXTRACTION
          ↓
      FILE FOUND?
          ↓
          NO
          ↓
CONTINUOUS MONITORING LOOP
          ↓
SOURCE MONITORING PLATFORM
```

### Requirement

The system shall not terminate the overall monitoring service when no file is found.

Instead, it shall return to the monitoring process.

## FR-09 — TERMINATE

```text

```

### Requirement

### Important Clarification

This termination applies to the current document-processing/storage branch.

It does not mean that the entire FT-07 monitoring system stops.

The system continues its overall monitoring operation according to the continuous monitoring loop.

# 32. FINAL PRODUCT DEFINITION

**FT-07 is a continuous regulatory monitoring and AI-assisted compliance information platform that monitors only RBI and SEBI websites through a backend Source Monitoring Platform that web-scrapes those websites for new notifications/files. The scraped information is processed by Watchdog Extraction, which determines whether a new file has been found. If no file is found, the system returns to the continuous monitoring loop. If a file is found, it passes through OCR, SHA256/encryption and original-document storage before the current storage branch terminates. The OCR data then passes through Document Cleaning and NLP, where it is analyzed and compared against trained company compliance policies. NLP produces three outputs: a 1-line representation, detailed information and a summary. These outputs pass through a single Supabase Backend into the Web Application. The user is notified to log in, with the 1-line NLP output used as the notification title and the Summary used as the notification description. When the user clicks the notification, the system opens the relevant information and provides a brief of the detailed NLP data. The user can then activate a Voice Button, which triggers 11Labs, after which an LLM handles questions with respect to the relevant context. The mobile experience is provided through a Mobile App → App Shell Architecture → WebView Container → WebView path.**
